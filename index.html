USB Power Delivery (PD)規範

Chapter 1. Introduction (簡介與版本演進)

30 秒重點

USB PD 讓 USB-C 的供電最高到 240W，並在 CC 線上協商電力與資料。

  • 版本演進：PD 2.0（2014）導入 Power Rules，PD 3.0（2015）加入 PPS、FRS，PD 3.1（2021）加入 EPR 與 AVS，PD 3.2 於 2023 年首次發布。
  • 功率分兩段：SPR 最高 100W（20V／5A），EPR 最高 240W（48V／5A）。
  • PD 是雙向的：設備可以供電也可以受電，例如螢幕幫筆電充電。

最常被誤會的是版本與功率的對應，先看下面的對照表。

USB Power Delivery (PD) 是一種電力傳輸標準，允許 USB 線纜和連接器為各式設備提供高達 240W (48V/5A) 的電力。除了電力傳輸外，USB PD 還支援在 USB-C 上進行數據協定協商。

實務觀點：USB PD 2.0 vs PD 3.0 vs PD 3.1/3.2 電壓與協議綜合對照表

PD 2.0 導入了 Power Rules (電源規則)，取代了 PD 1.0 的固定 Profile；而 PD 3.0 則進一步導入了 PPS (動態調壓)、FRS (無縫角色切換) 以及更豐富的狀態訊息。到了 PD 3.1/3.2，則加入了 EPR (Extended Power Range)，支援 28V、36V、48V，將功率上限推升至 240W，並引入 AVS (Adjustable Voltage Supply)。

  • 可協商的功率輸出：支援高達 240W 的協商能力。
  • 雙向電力 (Bidirectional power)：設備既能提供電力也能消耗電力（例如螢幕為筆電充電）。
  • 數據協定協商：允許切換至 DisplayPort、USB4 或 Thunderbolt 等交替模式 (Alternate Modes)。

Chapter 2. Glossary and Info (術語與資訊)

30 秒重點

  • SPR 是 Standard Power Range，EPR 是 Extended Power Range。
  • APDO 是 PPS 與 AVS 共用的資料物件格式，不是第四種獨立電源。
  • PPS 可微調電壓並限流，AVS 可調電壓但沒有可程式化的電流限制。

Chapter 3. Port Power Requirements (端口電源需求)

30 秒重點

Source 能提供多少電流，取決於它的額定功率 PDP。

  • PDP ≤ 15W 的 Source 只需要 5V，電流 = PDP ÷ 5。
  • PDP 在 45W 到 100W 之間，5V、9V、15V 都要提供 3A，20V 的電流 = PDP ÷ 20。
  • 5V Fixed PDO 一定是 Source_Capabilities 的第 1 個 PDO。

電源需求定義了相容 USB PD 的 Source 必須提供的電壓與電流範圍，確保跨設備生態系統的互操作性。

Chapter 4. Power Delivery Electrical Requirements (電氣需求)

30 秒重點

電氣需求規範 VBUS 轉換要多快、多穩，以及保護機制。

  • 新電壓要在規定時間內穩定在 vSrcNew 範圍內，上升速率有上限。
  • Source 需要 OCP、OVP、OTP 三種保護。
  • 斷開時，VBUS 必須在 tSafe5V（最長 275ms）內降到 vSafe5V（4.75～5.5V）以下。
  • 正向轉換 (Positive Transitions)：新電壓需在規定時間內穩定於 vSrcNew 範圍內，最大轉換率受 vSrcSlewPos 限制。
  • 保護機制：Source 需具備 OCP (過流保護)、OVP (過壓保護) 以及 OTP (過溫保護)。

Chapter 5. Physical Layer (物理層架構)

30 秒重點

PD 通訊分三層：BMC 實體層、協定層、Policy Engine。

  • 實體層（BMC）只負責把位元變成 CC 上的電壓波形，不管內容。
  • 協定層負責組封包、回 GoodCRC、重送。
  • Policy Engine 由 MCU 執行，決定要宣告什麼電力、要不要接受請求。

BMC 的細節與編碼工具在 Chapter 6，封包欄位在 Chapter 7。

USB PD 使用 Bi-phase Mark Coding (BMC) 作為 CC 線的通訊實體層協定。

實務觀點：BMC 實體層與 PD 協議引擎的 OSI 模型對應

在系統架構中，兩者分屬不同層級，緊密合作：

  • [OSI 第 1 層] BMC 實體層 (PHY)：負責將數位 0/1 與 CC 線上的實體電壓波形相互轉換 (Bit Stream 層級)，類似「郵差」，只負責精確發送與讀取電壓跳變，不理會內容。
  • [OSI 第 2/3 層] PD 協議引擎 (Protocol Engine)：負責封包組裝/拆解 (Header/Payload)、自動 Ack (GoodCRC) 與重試機制，類似「審稿員」，檢查信封格式並解析指令意義。
  • [OSI 第 3/4 層] Policy Engine：主控 MCU 負責制定電源規則與決策。

Chapter 6. BMC 訊號編碼與電氣特性

30 秒重點

BMC 是 CC 線上的編碼方式：每個位元週期開頭都跳變，1 在中間再跳一次。

  • 速率 300 kbps（規範允許 270～330 kbps），1 UI 約 3.33µs。
  • 實際封包先做 CRC-32 與 4b5b，再加 Preamble、SOP* 與 EOP，最後才轉成 BMC 波形。
  • 發送端電壓擺幅 vSwing 為 1.05～1.2V，封包之間至少隔 25µs。

Bi-phase Mark Coding (BMC) 是一種半雙工、直流平衡 (DC balanced) 的通訊方式，透過 CC 腳位傳輸資料。

實務觀點：編碼邏輯與頻率
  • 0/1 編碼邏輯 (Transition-Based)： 每個位元週期 (1 UI) 的開頭一定會跳變一次；邏輯 0 在週期中間保持不變，邏輯 1 則在週期中間再跳變一次。
  • 標稱傳輸率與頻率： 傳輸率為 300 kbps（規範允許 270～330 kbps，1 UI 約 3.33 μs，範圍 3.03～3.70 μs）。波形實際跳變頻率落在 150 kHz ~ 300 kHz。
  • 電氣準位： 發送端電壓擺幅 vSwing 為 1.05V ~ 1.2V（標稱 1.125V），上升／下降時間 tRise／tFall 不可超過 300ns；封包之間至少間隔 tInterFrameGap 25μs。接收端則依 Rx Mask 判讀，Mask 中心線依是否正在供電、受電或兩者皆無，分別為 0.6875V、0.4375V、0.5625V。

Chapter 7. Protocol Message Definitions (協定訊息定義)

30 秒重點

每則 PD 訊息都是「Preamble＋SOP*＋Header＋Data Objects＋CRC＋EOP」。

  • Header 16 位元，包含 Message Type、Spec Revision、Data／Power Role、MessageID、資料物件數。
  • Spec Revision：01b 是 2.0，10b 是 3.x（3.0、3.1、3.2 共用），11b 為 Reserved。
  • 每則訊息收到後，接收端都要回 GoodCRC；沒收到會重送，最多 2 次（PD 3.x）。

常見誤解：Spec Revision 不是 3.1 專用值，3.x 全部共用 10b。

封包結構文字說明 (Message Construction Breakdown)

USB PD 封包由以下 5 個主要區塊組成：

  • Preamble (前導碼)： 用於同步並指明封包開頭的訊號序列 (Synchronization sequence to indicate the start of a packet)。
  • Header (訊息標頭)： 16-bit 的核心控制標頭，定義封包屬性與角色狀態。
  • Data Objects (資料物件)： 包含 0 至 7 個 32-bit 的資料內容。
  • CRC (循環冗餘校驗)： 用於偵錯與確認資料傳輸完整性。
  • EOP (End of Packet)： 標示封包結束。

Data Objects (資料物件) 種類：

  • Power Data Object (PDO)： 宣告 Source/Sink 供受電能力。
  • Request Data Object (RDO)： Sink 發出的具體電力請求。
  • BIST Data Object (BDO)： 內建自我測試資料物件。
  • Vendor Defined Object (VDO)： 廠商自定義物件（用於 Alt Mode 協商或 E-Marker 讀取）。
  • Battery Status Data Object (BSDO)： 電池狀態資料物件。
  • Alert Data Object (ADO)： 警報狀態資料物件。
實務觀點：控制封包 vs 數據封包

1. 控制封包 (Control Messages)

僅含 16-bit Header，無 Payload。用於狀態控制：

  • GoodCRC：收到合法封包後必須在 195μs 內自動回傳。
  • Accept / Reject：同意或拒絕請求。
  • PS_RDY：Source 電壓切換完成並穩定後發送。
  • Soft / Hard Reset：重置狀態機或將 VBUS 拉回 5V。

2. 數據封包 (Data Messages)

16-bit Header + 32-bit Data Objects：

  • PDO：Source/Sink 宣告供受電能力 (Source_Capabilities)。
  • RDO：Sink 發送的具體電力請求 (Request)。
  • VDO：VDM 封包中用於 DP Alt Mode 協商或讀取 E-Marker。

Chapter 8. PDO / RDO 詳解

30 秒重點

Source 用 PDO 宣告能力，Sink 用 RDO 指定要哪一個。

  • PDO 有 Fixed、Battery、Variable 與 APDO（PPS、SPR AVS、EPR AVS）幾種格式。
  • RDO 的 Object Position 是「第幾個 PDO」，從 1 開始數；Operating Current 是 Sink 會抽的最高電流。
  • 協商順序是 Source_Capabilities → Request → Accept → PS_RDY，Accept 時 VBUS 還沒變，PS_RDY 才代表電壓到位。
  • 被 Reject 代表這個請求不行，被 Wait 代表稍後再試（至少等 100ms）。

常見誤解：RDO 的 Max Operating Current 已棄用，要填成和 Operating Current 一樣。

互動工具：協商流程動畫、PDO／RDO 解碼工具

Source 透過 PDO 宣告其供電能力，而 Sink 則透過 RDO 向 Source 提出具體的電力請求。

  • Fixed Supply PDO (固定電壓)：5V Fixed PDO 必須永遠作為 Source 宣告的第一個 PDO。
  • Variable / Battery / Augmented PDO：涵蓋浮動電壓、電池直供與 PPS/AVS。
  • RDO (Request Data Object)：Sink 藉由 Object Position 指定選擇的 PDO，並設定 Operating Current 與 Capability Mismatch 標籤。

Chapter 9. PPS (Programmable Power Supply)

30 秒重點

PPS 讓 Sink 在小範圍內精細調電壓並限流，適合鋰電池直充。

  • 電壓步進 20mV，電流限制步進 50mA。
  • PPS APDO 的最高電壓只有 11V、16V、21V 三種，最低 5V（3.3V 已棄用）。
  • 兩種模式：恆壓（CV）與限流（CL），CL 時會用降低電壓來避免觸發 OCP。

PPS 允許設備在一定範圍內進行極其精細的電壓與電流調節，以適應鋰電池直充的高效率轉換需求。

  • 電壓步進：20mV (vPpsStep)
  • 電流限制步進：50mA (iPpsCLStep)

PPS 支援兩種工作模式：恆壓模式 (CV) 維持電壓輸出；限流模式 (CL) 則在 Sink 抽取電流超過設定值時，透過主動降低電壓來避免觸發 OCP 過流保護。

Chapter 10. 關於 12V PDO 的特殊考量

30 秒重點

12V 不是 PD 規範的標準固定電壓，市面上的 12V 輸出多半是相容性做法。

  • 規範固定電壓檔位是 5V、9V、15V、20V。
  • 常見 12V 來自相容 QC 等舊協議、客製非標 PDO，或車用 12V 環境。
  • 正規做法是用 PPS／AVS 的 APDO 直接請求 12.00V。

在 USB PD 規範的嚴格 Power Rules 中，12V 並非標準強制要求的固定電壓 (Normative Fixed Voltage)，強制規範的檔位為 5V, 9V, 15V, 20V。

實務觀點：為何市面上仍常見 12V 輸出？
  • 跨協議相容性： 許多 Adapter 採用多協定晶片，需支援 QC 2.0/3.0 等依賴 12V 的傳統快充協議。
  • 非標 PDO 客製化： 廠商為相容歷史遺留的 12V DC 設備 (如硬碟盒、車用電子)，會在 FW 寫入 12V PDO。
  • 原生車用 12V 環境： 車充輸入端為 12V 鉛酸電池，直通或轉換 12V 效率最高。
  • 正規解法 (PPS)： 現代 Sink 可透過 PPS/AVS APDO (如 3.3V~21V) 以微調方式精準請求 12.00V，完全符合 PD 3.0 標準。

Chapter 11. PD Source (供電方) 與 Rp/Rd 基礎供電

30 秒重點

Source 在 CC 上用 Rp 宣告預設電流，Sink 的 Rd 與它分壓後得到電壓。

  • Default USB、1.5A、3.0A 分別對應 Rp 56kΩ、22kΩ、10kΩ（上拉到 5V），或電流源 80µA、180µA、330µA。
  • Sink 的 Rd 是 5.1kΩ，CC 電壓約 0.41V、0.92V、1.68V，Sink 依此判斷可抽電流。
  • Source 要看到 Rd 持續 tCCDebounce（100～200ms）才開 VBUS。

Chapter 12. PD Sink (受電方) 運作機制

30 秒重點

Sink 靠 5.1kΩ Rd 被 Source 偵測到，還要管好大電容與電壓轉換期間的耗電。

  • 拔除時，Sink 要讓 VBUS 在 tSafe5V 內降到 vSafe5V 以下。
  • Source 轉換電壓時，Sink 進入 Sink Standby，電流要降到 iSnkStdby（最大 500mA）以下。

PD Sink 是消耗 VBUS 電力的設備，在 CC 線上掛載固定的 5.1kΩ 下拉電阻 (Rd) 以與 Source 的 Rp 形成分壓。

Sink 必須妥善管理大容量輸入電容 (Bulk Capacitance)，在設備拔除時於 tSafe5V 內快速放電。此外，當 Source 準備轉換電壓時，Sink 必須進入 Sink Standby 狀態，將消耗電流降至極低 (iSnkStdby)，協助電壓平順轉換。

  • 切換週期 tDRP 為 50～100ms，Source 時間占比 30%～70%。

Chapter 14. USB Type-C 腳位定義與設備偵測

30 秒重點

Type-C 有 24 個腳位，CC 上的 Rp／Rd／Ra 組合決定了對面是什麼。

  • CC1／CC2 其中一支負責通訊與偵測，另一支在需要時變成 VCONN。
  • Rd 加 Open 是一般 Sink；Ra 加 Rd 是帶 E-Marker 的線纜加 Sink。
  • 雙 Rd 是 Debug Accessory，雙 Ra 是 Audio Adapter Accessory。

USB Type-C 介面共有 24 個腳位 (Pins)，其對稱的設計實現了正反插功能。本章節總結了各組訊號的實務配置與作用。

一、 基礎腳位定義與用途

  • VBUS & GND (電源與接地)： 包含 4 個 VBUS (A4, A9, B4, B9) 與 4 個 GND (A1, B1, A12, B12)。預設 VBUS 為 5V，在 PD 快充協議下可提升至最高 48V/5A (240W)。
  • D+ / D- (USB 2.0 差分訊號)： A6, A7, B6, B7。保留 4 個腳位以支援正反插，但實際通訊僅會使用其中一對 (半雙工)，最高支援 480Mbps。
  • TX / RX (USB 3.x 高速差分訊號)： 共 8 個腳位 (A2, A3, B2, B3 與 A10, A11, B10, B11)。分開的 TX/RX 實現了全雙工 (Full-duplex) 高速傳輸 (5Gbps ~ 40Gbps+)。
  • SBU1 / SBU2 (SideBand Use)： A8, B8。用於 Alternate Mode (例如在 DP Alt Mode 下作為 AUX+ / AUX- 訊號) 或 Audio Adapter Accessory Mode (作為麥克風輸入與類比接地)。
  • CC / VCONN (配置通道)： A5, B5。其中一根作為 CC 線負責通訊與偵測，另一根則切換為 VCONN，為線纜內的 E-Marker 晶片提供供電。
實務觀點：CC 腳位的多重功能與設備狀態偵測

CC (Channel Configuration) 腳位除了作為 BMC 數位通訊的實體層外，在硬體底層還負責：插拔偵測、正反插方向確認、初始電流能力廣播。

Host (供電端) 可以透過偵測 CC 腳位上的電阻組合，來精準判斷連接的設備類型。常見的電阻包含：Rp (Host 端上拉)、Rd (Device 端下拉 5.1kΩ)、Ra (線纜端下拉 800~1200Ω)。

Chapter 15. Dead Battery 機制與 CC 5.1kΩ 下拉電阻

30 秒重點

Dead Battery 時，Sink 用 Rd 或電壓箝位讓 Source 先給 5V，之後再交給系統接管。

  • 兩種硬體做法：Depletion-mode MOSFET Rd，或電壓箝位（約 1.1V）。
  • 箝位無法分辨電流宣告，也會擋住 PD 通訊，要等系統起來後換成 Rd。
  • 交接空窗期 Rd 消失超過 tSRCDisconnect（約 20ms），Source 會當成拔除而斷電，造成開機斷電迴圈。

常見誤解：tCCDebounce（100～200ms）是連接偵測用，不是這個空窗期的時限。

互動工具：Dead Battery 動畫

Dead Battery（沒電狀態）機制與 CC 腳位上的 5.1kΩ 下拉電阻 (Rd) 是唇齒相依的設計，目的是解決「當裝置完全沒電、系統主控 IC 無法運作時，要如何讓充電器願意送電出來」的難題。

一、為什麼需要 5.1kΩ (Rd)？

Type-C 基本偵測邏輯中，Source 端在 CC 腳位掛上拉電阻 (Rp)，Sink 端必須掛 5.1kΩ 到地的下拉電阻 (Rd)。裝置處於 Dead Battery 狀態時，系統沒有任何 VDD/VCC 可驅動 GPIO 或邏輯電路——若此時接上充電器卻偵測不到 Rd，充電器會判定「沒有裝置插入」，VBUS 絕不會輸出電壓。

二、TCPC 的 Dead Battery 硬體實作

為了在「無電可用」狀態下依然呈現 5.1kΩ，支援 Dead Battery 的 TCPC (Type-C Port Controller) 具備特殊硬體結構：

  • 常閉型下拉機制： 利用 Depletion-mode MOSFET（空乏型金氧半場效電晶體）等無源電路設計，當 TCPC 主電源 (VDD) 為 0V 時，內部 5.1kΩ Rd 會自動且預設地連接到 CC 腳位。
  • DRP (Dual Role Power) 的降級： 即使裝置設計為 DRP，在 Dead Battery 狀態下 TCPC 會強制將自己配置為 Sink（掛上 Rd），因為此時系統根本沒有電源可提供 VBUS 輸出。

實例：TI TPS66994C 以「電壓箝位 (Clamp)」呈現 Rd

實際的 PD 控制器不一定在 CC 上放一顆真的 5.1kΩ 電阻。以 TI TPS66994（B/C 版，2 埠 DRP PD 控制器，datasheet 8.3.5.3 Dead Battery Advertisement）為例，它支援從無電池或電池耗盡的狀態，直接靠 Px_VBUS 供電開機；晶片在沒有供電時，用硬體把 Px_CCy 的電壓箝位在 VCLAMP，讓 CC 呈現的電壓與 Rd 相同，Source 就會當成看到 Rd 而送出 VBUS。

  1. 實體層喚醒： TCPC 在無電狀態下靠硬體呈現 5.1kΩ Rd，充電器偵測到後輸出 vSafe5V 到 VBUS。
  2. TCPC 供電： VBUS 的 5V 進入 TCPC，內建的小型 LDO 轉換成 3.3V，供應內部邏輯電路或讓系統端 EC/TCPM 開機。
  3. TCPM 接管 (Takeover)： 系統的大腦 (TCPM) 開機完成後，透過 I2C 初始化 TCPC。
  4. 電阻切換： TCPM 下達指令，將 TCPC 從「硬體 Dead Battery Rd」無縫切換成「暫存器控制的 Active Rd」。
  5. 啟動 PD 協議： 系統已具備運算能力，TCPM 透過 CC 線發送 BMC 訊號，請求 Source Capabilities，並發送 RDO（例如要求 20V/3A）以進入快充狀態。

Chapter 16. Fast Role Swap (FRS) 機制

30 秒重點

FRS 讓 Hub 掉電時，新的 Source 在硬體層面接手供電，VBUS 不中斷。

  • FRS Signal：≤5Ω 拉低 CC，持續 60～120µs，接收端偵測 30～50µs。
  • 新 Source 必須在 VBUS ≤ vSafe5V 後 150µs（tSrcFRSwap）內開始供電。
  • 硬體階段之後，FR_Swap、Accept、PS_RDY 這些 PD 訊息是毫秒級，各自 ≤15ms。

常見誤解：150µs 不是整個角色切換的時間。

互動工具：FRS 時序圖

Fast Role Swap (FRS) 是 USB PD 3.0 引入的關鍵功能，解決的痛點是：當帶有供電能力的集線器 (Hub) 或擴充基座 (Dock) 突然被拔除外部電源時，如何確保連接在上面的裝置（如隨身碟、硬碟）不會因為斷電而導致資料傳輸中斷。

傳統的 PR_Swap (Power Role Swap) 由軟體（TCPM 的狀態機）主導交握，耗時長達數十到數百毫秒，VBUS 必定掉電，連帶 Data Role 也跟著中斷重連。FRS 的核心概念是：透過純硬體的實體層訊號，讓新的 Source 在極短時間內（150µs，即 tSrcFRSwap）接手供應 VBUS，讓原本吃電的裝置 (Sink) 瞬間變成供電的裝置 (Source)，維持 VBUS 在 vSafe5V 不掉電。後續的 FR_Swap、Accept、PS_RDY 訊息再用毫秒級的時間把角色交換補完。

一、FRS 的硬體觸發機制與時序

FRS 的觸發完全繞過冗長的 PD 封包傳遞，直接在 CC (Configuration Channel) 腳位上做文章：

  1. 初始狀態： 假設筆電目前是 Sink（受電端，吃 Hub 的電），Hub 是 Source（供電端）。
  2. Hub 外部斷電 (FRS 觸發)： Hub 偵測到外部電源被拔除，其 TCPC 會立刻以 ≤5Ω 的電阻 (rFRSwapTx) 將 CC 腳位拉低到接地，持續 tFRSwapTx（60～120µs），此動作稱為 Fast Role Swap Signal (FRS Signal)。接收端以 vFRSwapCableTx（約 490～550mV）為偵測門檻。
  3. 筆電端偵測： 筆電端 TCPC 內部有專用的類比比較器，一旦偵測到 CC 低電位持續達 tFRSwapRx（30～50µs），就判定收到 FRS 訊號。
  4. 角色互換與供電接手 (150µs 死線)： 舊的 Source (Hub) 須關閉 VBUS 輸出、開啟 VBUS 消耗路徑準備成為 Sink；新的 Source (筆電) 須在 VBUS 降到 vSafe5V (max) 以下之後的 150µs (tSrcFRSwap) 內，開始以 vSafe5V 供電，接手向 Hub 供電。

二、對硬體研發工程師的設計挑戰

1. TCPM 的 I2C 延遲是致命傷

TCPM 依賴 I2C 讀寫 TCPC 暫存器。若 TCPC 收到 FRS 訊號後只透過 ALERT# 通知 TCPM，等 TCPM 喚醒、讀取狀態、再下達開啟 VBUS 的指令，絕對來不及趕上 150µs 的死線。硬體解法：支援 FRS 的 TCPC 通常會有一個實體硬體腳位（例如 FRS_EN 或 GPIO_0），當 TCPC 偵測到 FRS 訊號時，直接由硬體邏輯拉高該腳位，越過 TCPM 直接開啟 5V 供電路徑。

2. Load Switch 的開啟時間與 Inrush Current

筆電要瞬間送出 5V 接手供電時，通常透過一顆 Load Switch（例如 DPS1133 這類電源開關 IC）。若 Load Switch 開得太慢（例如為了 Soft-start 刻意設定很大的 slew rate），VBUS 電壓會掉到系統重置點以下，FRS 宣告失敗；若開得太快，瞬間對 Hub 端的龐大電容充電，會產生極大的 Inrush Current (湧浪電流)，可能觸發 OCP (過電流保護) 導致斷電，甚至損壞元件。設計時必須精準調校 Buck-Boost 的瞬態響應能力、Load Switch 的啟動時間 (Turn-on time)，以及 VBUS 上的去耦電容 (Decoupling Capacitors) 總量。

3. Active VBUS Discharge 的干擾

FRS 發生時，系統必須非常小心處理 VBUS 的主動放電 (Active Discharge) 電路。若舊的 Source 在切換過程中不慎觸發了放電電路，會將新的 Source 辛苦送出來的 5V 電壓瞬間拉低，導致切換失敗。

名詞對照：TCPC / TCPCi / TCPM
名詞 全名 角色與功能

Chapter 17. Alternate Mode (交替模式與音訊)

30 秒重點

Alt Mode 靠 VDM 協商，把 USB-C 腳位重新配置去傳 DP 等訊號。

  • 常見的有 DP Alt Mode 與 Thunderbolt。
  • 類比 3.5mm 音訊是 Accessory Mode（CC 雙 Ra），完全不經過 PD 或 VDM，不是 Alt Mode。
  • 有 DAC 的數位 USB 音訊走標準 USB 2.0，也不是 Alt Mode。

Alternate Mode (交替模式) 允許協商並重新配置 USB-C 的腳位 (Pins)，用以傳輸如 DisplayPort 等非 USB 訊號。此協商建立於 Vendor Defined Message (VDM) 之上。

實務觀點：Alt Mode 種類與 Type-C 音訊的釐清

常見 Alt Mode：

  • DP Alt Mode (0xFF01)： 佔用 TX/RX 對傳輸影像，SBU 傳 AUX，目前市場絕對主流。
  • Thunderbolt (0x8087)： 混合傳輸 PCIe、DP 與 USB，旗艦效能標準。

特別釐清：Type-C 音訊輸出是 Alt Mode 嗎？

不是！ 類比聲音輸出與 Alt Mode 具備本質上的區別：

  • 類比音訊 (Accessory Mode)： 傳統 3.5mm 轉接頭內部將 CC1/CC2 同時下拉 1kΩ (雙 Ra)。這純粹是硬體觸發 Mux 切換類比訊號至 DP/DN 與 SBU，完全不依靠 USB PD 數位封包與 VDM 握手。
  • 數位 USB 音訊 (USB Audio Class)： 內建 DAC 晶片的小尾巴，走的是標準 USB 2.0 (DP/DN) 數據列舉與數位通訊，亦非 Alt Mode。

Chapter 18. E-Marker 晶片與線纜通訊機制

30 秒重點

5A 線纜需要 E-Marker 才能證明自己能承載 5A，否則 Source 最多只給 3A。

  • Source 偵測到 Ra 後，把未連通的 CC 腳改成 VCONN 供電給 E-Marker。
  • E-Marker 只回應 SOP' 與 SOP''，不理會一般 SOP。
  • Source 用 Discover Identity 讀取線纜能力，確認後才在 Source_Capabilities 提供超過 3A 的選項。

在 USB Type-C 與 USB PD 規範中，E-Marker (Electronically Marked Cable Assembly，電子標籤晶片) 的溝通是一套高度結構化的硬體與協議互動流程。對於 5A 線材而言，若沒有 E-Marker 晶片向供電端（Source）確認其具備 5A 承載能力，系統出於安全保護機制，最高只會允許 3A 的電流（即傳統的 60W 上限）。

E-Marker 晶片透過 CC 引腳與設備進行溝通，其核心運作機制可以分為以下四個主要階段：

1. 物理連接與供電階段 (VCONN 激活)

當使用者將 5A 線材插入供電端與受電端時：

  • 接腳分配： USB-C 插頭中雖然有兩個 CC 引腳（CC1 與 CC2），但在線材內部，只有一根實體線會將兩端的 CC 引腳連通。另一個未連通的引腳則會在插頭處連接一個下拉電阻 Ra (約 1kΩ)。
  • 偵測與供電： 供電端透過檢測到 Ra 的存在，判定該線材含有 E-Marker 晶片。隨後，供電端會將這個未連通的 CC 引腳定義為 VCONN，並向其輸出 5V 的電壓，正式為線材內部的 E-Marker 晶片供電並將其喚醒。

2. 協議層的通訊對象 (SOP 通訊機制)

在 USB PD 的物理層，通訊是透過 BMC 訊號在 CC 總線上進行半雙工傳輸。為了區分通訊對象，協議定義了不同的「起點標記 (Start of Packet, SOP)」：

  • SOP： 供電端與受電端之間直接進行的通訊（例如電壓握手）。
  • SOP' (SOP Prime)： 供電端與距離其最近的插頭端 E-Marker 進行的通訊。
  • SOP'' (SOP Double Prime)： 供電端與遠端插頭（靠近受電端）的 E-Marker 進行的通訊（若為雙晶片線材）。

💡 提示： E-Marker 晶片只會聆聽並回應以 SOP' 或 SOP'' 開頭的數據包，對於常規的 SOP 數據包會直接忽略，從而避免干擾主設備之間的電壓協商。

3. 發現身份與宣告能力 (Discover Identity)

晶片通電並進入就緒狀態後，供電端會啟動查詢流程：

  • 傳送請求： 供電端向 CC 總線發送一個結構為 Discover Identity Request 的 SOP' 數據包。
  • 晶片回應： E-Marker 接收請求後，回覆 Discover Identity ACK。回應中包含了一組至關重要的 VDM (Vendor Defined Message) 數據結構。

在傳回的 VDM 中，E-Marker 會明確宣告：

  • 最大電流承載能力： 明確標註為 5A（若為 EPR 線材則會標註對應電壓如 28V/36V/48V）。
  • 數據傳輸速率： 宣告線材支援 USB 2.0、USB 3.2、USB4 或 Thunderbolt 速率。
  • 基本資訊： 包含製造商 ID (VID)、產品代碼 (PID) 以及線材長度與類型 (被動/主動)。

4. 功率合約的最終確立 (Power Contract)

一旦供電端成功讀取到 E-Marker 傳回的 5A 認證資訊，快充機制才會解鎖：

  • 宣告能力： 供電端隨後會以 SOP 數據包向受電端發送 Source Capabilities，此時的 PDO 宣告中才會正式包含 20V/5A (100W) 或更高（如 28V/5A 140W）的選項。
  • 接受合約： 受電端選擇適合的功率發送 Request，供電端回覆 Accept 後，VBUS 的電壓與電流即會調整至 3A 以上，完成高功率供電。
🛠️ 技術實作摘要：E-Marker 互動流程
[ 供電端 (Source) ]                                     [ E-Marker 晶片 ]
        |                                                       |
        |--- 偵測到 Ra 電阻，透過 VCONN 引腳供電 (5V) --------->| (晶片啟動)
        |                                                       |
        |--- 發送 SOP' 數據包 (Discover Identity Request) ------>|
        |                                                       |
        |<-- 回覆 SOP' 數據包 (宣告: 支援 5A, USB4, 廠商ID) -----| (完成身份識別)
        |
    [ 允許輸出 > 3A ]
        |
        |=============> 續與 [受電端 (Sink)] 進行 SOP 握手，建立 5A 功率合約

若在上述流程中，供電端發送 SOP' 請求後超時未收到回應（例如使用了無 E-Marker 的常規 3A 線材），基於安全考量，供電端在隨後發送給受電端的 Source Capabilities 中，絕對不會出現任何超過 3A 的電流選項，確保線材不會因超載而過熱融化。

Chapter 19. FW 設計規格與系統交付 Check List

30 秒重點

交付 FW 與硬體需求時，用這份清單確認有沒有漏項。

  • FW 策略：DRP 切換、Try.SRC／SNK、PDO 清單、熱管理、Mux 與 Alt Mode 控制。
  • 硬體與安規：MOSFET 驅動、VBUS 放電能否達到 tSafe5V、OVP／OCP 閾值、韌體更新失敗的回復機制。

練習填寫這份清單，可以看相關專案裡的 USB-PD-FW-Checklist。

做為系統開發者，在選定 DRP PD 控制晶片後，需向原廠或 FW 團隊交付具體的系統級軟硬體需求規格。以下為實務上必備的 Checklist：

1. 韌體策略 (FW Requirements)

  • DRP 策略：定義 Toggle 週期、是否開啟 Try.SRC/SNK、電池 <15% 時是否拒絕 PR_Swap。
  • 電力菜單：明確定義 Source PDOs (含非標 12V 需求) 與 Sink 運作功率。
  • 熱管理：板端 NTC >85°C 時主動降功率 (Thermal Throttling) 的觸發條件與恢復機制。
  • Mux 與 Alt Mode：定義 DP Alt Mode 的 Pin Assignment (C/D/E/F) 與 Mux 的 GPIO/I2C 控制邏輯。

2. 硬體與安規 (Hardware Specs)

  • 電源控制：MOSFET 開關的 VGS 驅動、VBUS 快速放電電路確保 tSafe5V 達標。
  • 保護閾值：OVP (通常設定為 Selected PDO + 120%)、OCP (Selected Current + 15%)。
  • ISP/OTA 備份：定義 Dual-Bank Flash 備份區，刷寫韌體失敗時自動 Rollback 的防呆機制。
